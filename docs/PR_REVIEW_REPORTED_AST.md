# 來源藥敏與人工審閱：本機 PR 差異審查

## 審查範圍與結論

本次由實作者完成本機差異審查，沒有另外建立或發布 GitHub PR。檢查 CSV 轉換、病例來源契約、來源判讀規則、模型輸入、RAG 範圍、審閱驗證與回歸測試。

預設流程已改用實際名稱與來源藥敏；歷史虛構資料只保留供回歸與歷史稽核。這是可操作的研究流程，尚非正式臨床決策系統。

## 審查中修正

- 參考文件新增適用族群 metadata；成人／兒童病例在候選產生前執行確定性片段篩選。族群不符或無法確認的片段不提供給模型，沒有合格片段或病例年齡未知時停止發布候選並要求人工確認。

- 原始報告與 CLSI 2022 衍生判讀分別保存；不把 I、SDD、NS 或缺漏轉成 S。版本標示不一致與同藥衝突不列入敏感選項。
- CSV 測量值可能屬不同方法且缺少單位，保留原始字串，不一律填入 MIC。
- 同名過敏只排除相關藥物；來源排除項目由後端保留，人工修改不能移回候選，也不能加入重複候選。
- 病例標示 hybrid 及 simulated_fields，不把去識別來源稱為全合成資料。來源病例外部生成預設關閉；本機模型可使用必要欄位。
- 病例分析與 benchmark 均按 evidence_scope 檢索，WHO 參考文件能進入來源病例流程；規則與證據保存執行快照。
- 瀏覽器測試改用獨立文件資料庫，避免前次文件版本造成誤判衝突。
- 離線準備改為選取來源病例，每次新增執行；先前文件不足造成失敗時，補齊文件可再次成功。
- CSV 與病人層級匯入產物已加入 Git 忽略，未提交原始資料。

後端歷史回歸測試明確指定舊規則；新來源測試及瀏覽器測試使用新的來源判讀規則與真實名稱、獨立撰寫的測試觀測值。

## 仍需分開看待的限制

- 初始病例採符合條件的前幾個培養，並非代表性抽樣；目前實際情境包含 E. coli 與 S. aureus。名稱字典涵蓋更多微生物與測試藥品，不等於已完成所有臨床情境。
- 症狀、人口資料、腎功能、過敏與目前用藥是明確補寫；CSV 無法還原真實完整病歷，也不能用來生成權威指引。
- 來源 S 只產生待審選項；不代表 WHO 已支持該藥物，也沒有完整感染適用性、交叉過敏、交互作用或腎功能調整引擎。
- 片段數及引用 ID 正確不等於內容支持結論，需要另做人工檢索品質評估。
- 早期驗證未呼叫付費 OpenAI；後續曾以獨立合成病例呼叫真實模型，但該 runtime 未提交 GitHub，本輪無法重現或核對最後 benchmark。mock 不代表模型推理。
- 沒有新增正式登入、臨床醫囑或自動處方。
