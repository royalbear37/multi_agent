## 操作與驗證結果

### 三種決策與必填欄位

實際在未保存狀態測試：

- amoxicillin_clavulanate → `採用`
- amikacin → `有條件採用`
- ampicillin → `不採用`

畫面行為：

- 三種決策都會顯示 `理由` 欄。
- `有條件採用` 另外顯示 `使用條件`，提示例為 `例如需先核對或處理的併用藥限制`。
- 未填完整理由／條件或未勾警示確認時，`保存逐藥決策` 不可用。
- 三筆理由、條件填齊並勾選共同警示後，摘要顯示 `本次選擇 3 項；未選項目維持未決定。`，保存按鈕才啟用。
- 將三項全部切回 `未決定` 後，摘要恢復 `本次選擇 0 項；未選項目維持未決定。`，保存按鈕再次不可用。

沒有按保存。

### 有條件採用的驗證細節

另以 amikacin 單獨測試：

1. 選 `有條件採用`。
2. 填理由、保持使用條件空白並勾警示。
3. 保存仍不可用。
4. 填入使用條件後，原有警示勾選會自動撤銷，保存仍不可用。
5. 重新勾選警示後，保存才啟用。
6. 切回 `未決定`，不保存。

這能避免使用者在修改條件後沿用舊的警示確認，行為合理。

### 警示確認只需一次

只要本次有任何逐藥決策，表格底部顯示單一共同勾選：

`已閱讀所選藥品的系統警示與未完成項目；保留上述限制並記錄我的決策。`

多選三個藥時也只有一個勾選框。修改任一決策內容後，該勾選會重設，需重新確認。

### 共同病例資訊只顯示一次

表格上方顯示 `病例資訊（共同核對一次）`，內容包括：

- `病例已記錄無已知過敏；一般過敏警語不等於缺少過敏史，不需逐藥重填。`
- `病例已確認目前無用藥；文件中的交互作用警語不代表本例正在併用。`

各藥列會保留該藥的禁忌或注意事項，但沒有逐藥再次要求輸入過敏史或目前用藥。共同資料的層級清楚。

### 未知與系統狀態

- ertapenem 與 levofloxacin 的列首明示 `AI 藥敏核對：未知`。
- imipenem 的過敏與 ampicillin 的交互作用顯示 `尚未確認`，沒有偽裝成已排除風險。
- tetracycline 顯示 `AI 藥敏核對：抗藥`，並另寫 `來源核對為抗藥，保留此警示供醫師判斷。`
- 每列均顯示 `系統尚待確認`、`整合評估未完成`、`尚未完成獨立引用複核`，以及 `系統核對尚未完成；醫師決策不會將它改為已通過。`

以上足以讓醫師知道逐藥選擇是人工紀錄，不是將 AI 狀態改為通過。

## 問題／中高：ertapenem 的「未知」與展開內容的敏感判讀互相衝突

**重現步驟**

1. 在逐藥醫師決策找到 ertapenem。
2. 先讀列首狀態。
3. 展開 `引用與完整初評`。

**實際所見**

- 列首：`AI 藥敏核對：未知`
- 展開後第一句：`AST結果顯示Escherichia coli對ertapenem敏感。`
- 接著寫：`藥品標籤指示ertapenem適用於複雜尿路感染。患者腎功能正常，無禁忌。`
- 警示：`引用適用性尚未驗證。目前只確認引用片段存在；尚未證明其中的感染部位、病原條件與此病例相符。條件不符時，請勿接受該候選。`

**醫師可能如何誤解**

列首的 `未知` 表示系統沒有完成藥敏來源核對，但展開後的第一句直接說 AST 敏感。現有警示主要限制引用的感染部位與病原適用性，沒有指出「敏感」這句與目前選定的藥敏來源狀態衝突。醫師可能把展開文字視為比列首更完整的資訊，而忽略 `未知`。

**建議**

- 在展開內容前加上：`模型草稿曾稱敏感，但選定的藥敏來源未通過核對；目前系統狀態仍為未知。`
- 將矛盾句放入 `模型原文（與來源核對不一致）` 區塊，而不是直接作為展開摘要第一句。
- 選擇 `採用` 或 `有條件採用` 時，在理由欄旁再次顯示 `藥敏核對未知`，避免長表中遺失列首狀態。

## ertapenem 修正複驗與結案

只複驗同一 run 的 ertapenem 列，沒有重跑其他交互或提交資料。

未展開 `引用與完整初評` 時，列內已直接顯示：

`藥敏判讀尚未核實；即使下方模型初評提到「敏感」，也不能當成已確認的藥敏結果。`

展開後，原本容易被誤讀成系統結論的句子已改成：

`原始模型初評（須與藥敏及獨立複核分開核對）：AST結果顯示Escherichia coli對ertapenem敏感。...`

其後仍保留引用適用性尚未驗證的警示。列首的 `AI 藥敏核對：未知`、未展開即見的未知警示、展開後的原始模型標籤三者一致，已能清楚表達「模型曾稱敏感，但系統沒有核實藥敏判讀」。

本報告所列 ertapenem 誤讀問題可標記為已修正；本次逐藥醫師決策 QA 結案，未發現剩餘操作阻擋。
