# 1.5.0 逐藥醫師決策與操作稿

2026-10-09。依使用者選擇，醫師可逐藥採用／有條件採用／不採用，填理由並保留系統警示。這是獨立人工決策紀錄，不會重寫 AI 分層、病例事實或引用複核結果。

## 可直接照做的 DEMO

1. 開啟 `http://127.0.0.1:5173/`，選擇 `agent-complete`，在歷史紀錄開啟 v12：`6d05f0aa-5f57-43b9-a54d-e133e81b9657`。
2. 分析結果可看到 18 個待確認藥品、沒有完成系統核對的候選。這是既有分析結果，不是新版又執行了一次模型。
3. 開啟「人工審閱」，查看「病例資訊（共同核對一次）」：病例已記錄無已知過敏，不再逐藥要求重填。未記錄的病例仍顯示未知，不自動當成沒有過敏。
4. 在「逐藥醫師決策」表查看藥敏衝突、用藥注意、來源缺口與獨立複核狀態。「引用與完整初評」可展開原始內容。一般交互作用警語不等同本例實際正在併用。
5. 對想處理的藥品選擇「採用」「有條件採用」或「不採用」，填寫理由。有條件採用另填具體使用條件，例如需先核對或處理的併用藥限制；請依實際文件及醫師判斷填寫，不將範例當成實際藥品禁忌。
6. 採用或有條件採用須勾選已閱讀所選藥品的警示。未選藥品保持未決定，無須處理整張表才能保存。理由或決定修改後須重新勾選。
7. 按「保存逐藥決策」。右側歷史顯示每項決定、理由、條件及原系統狀態；按「匯出醫師決策與原始警示」下載 JSON。原分析的匯出和候選狀態保持不變。
8. 舊「整份 AI 結果審閱（原有流程）」仍可展開；不允許用它把尚未完成核對的藥品偷偷提升為 AI 完整候選。

## 界線與後續

新版 Agent 提示分開一般警語、病例缺漏與證據缺口，尊重明示無過敏的病例資料；這只影響下一次分析。舊 v12 的模型原文保留，主表略去可確認是重問既有過敏史的一般提醒，仍可展開原始初評。

本輪未新增付費 live；v12 的既有一次授權已用完。1.4.2 輸出預算及 1.5.0 提示尚未經新 live 驗證。v12 的 WHO／DailyMed 錯配與未完成獨立複核仍是原分析限制；新增人工決策不代表这些問題已解決。後續新 live 需明確授權資料、目的地與一次費用，再逐項核對來源。

目前角色是展示用角色、審閱者為 demo-user，並非真實臨床身分認證；驗收的是功能實際執行、來源保存與可操作缺口，不是專家已確認臨床正確性。

後續可讀性改善：18 藥表格仍長，可增加「只看已決定／未知／抗藥」篩選；醫師 QA 判定目前不阻擋操作，未納入本輪修改。
