## 尚未由本角色在瀏覽器確認的 v7 項目

以下項目均維持「未驗證」，不能視為通過或失敗：

1. AST、證據與整合的 pending 草稿是否預設折疊，且折疊後仍能理解最終狀態。
2. 藥名旁的「待確認」是否足以壓過草稿內「有支持／適合使用」造成的推薦印象。
3. 臨床風險 Agent 失敗時，是否清楚顯示病例已有的過敏、腎功能與用藥資料，並明示其他 Agent 不能取代臨床風險核對。
4. Agent 的 issues 為空、但逐藥項目包含 uncertain 時，是否會出現明確且可操作的提示。
5. 文件與證據表格警告是否已中文化，raw code 是否確實收進技術折疊且不干擾主要流程。
6. 過敏狀態原本的 `已有評估排除紀錄` 是否已改為更明確的 ruled-out 用語。
7. 既有分析 `91ddb348-f6a6-4576-9926-989df2447128` 在上述改動後，是否仍存在實質誤導或操作阻擋。

## 後續復驗嘗試

同日再次依醫師角色進行唯讀復驗前，先用 CUA 檢查可用表面；`cua.getState()` 仍回傳 `apps: []`、`browsers: []`。因此沒有建立或操作任何分頁，也沒有另找 API、JSON、程式碼或其他繞路。

本次原定核對的下列項目仍未驗證：

- 文件庫中的 WHO 節錄是否已清楚標示為同一來源，避免被誤認成多份獨立證據。
- 舊 v7 結果的 pending 草稿折疊與「待確認」標示，是否足以避免被誤讀為推薦。
- clinical Agent 失敗時，病例已有資料、評估未完成及其他 Agent 不能取代核對的關係是否容易理解。

主執行者正在進行的已授權 live 分析沒有由本角色操作、等待或檢視；本角色沒有觸發新分析、外送、病例或文件保存，也沒有提交人工審閱。
