## 前端恢復後的唯讀復驗

前端恢復後，使用獨立 Edge QA 分頁重新開啟 `http://127.0.0.1:5173/`。本次只檢查 `agent-complete · revision 4` 中的既有歷史 run `91ddb348-f6a6-4576-9926-989df2447128`，沒有遍歷其他 run。

### 已確認改善

- 歷史 run 能在新版介面開啟，模式、執行方式與 run ID 顯示為：`獨立代理協作 · 選用已設定模型 · 91ddb348-f6a6-4576-9926-989df2447128`。
- 逐藥表的藥名旁直接顯示 `待確認`；最終欄顯示 `尚未通過完整核對，不能視為用藥建議。`
- 每個藥品的 `藥敏模型草稿（不等於治療建議）`、`查看模型證據草稿（尚非建議）`、`整合草稿與限制（尚非建議）` 均預設折疊。折疊狀態下，頁面可見文字不包含先前容易誤導的 `適合使用`、`良好療效` 或 `MIC值低`。
- 展開單一證據草稿後，肯定句仍存在於歷史模型原文，但前後已有 `模型初評`、`模型獨立複核回報`、`模型細項回報` 與 `尚未通過完整核對，不能視為用藥建議` 等限定詞。這比舊版直接平鋪清楚許多。
- 臨床風險欄顯示：`此 Agent 沒有可用評估；未核對不代表病例未提供資料。請查看病例摘要及執行錯誤。`
- 展開 `04 臨床風險 Agent · 執行失敗` 後，畫面明示：`本步驟沒有可用的風險結論，不能由其他 Agent 的肯定句取代。病例快照已有 過敏狀態、CrCl、eGFR、用藥清單完整性；請先查看下方執行錯誤，不需因為「未核對」就重填已有資料。`
- `03 證據 Agent · 需確認` 已把 issues 空但逐藥有 uncertain 的情況說清楚：`模型未另列缺漏清單，但逐藥結果有 2 項需注意或尚未完成核對；請查看下方對應理由與來源，不能解讀為全部通過。`
- WHO 節錄文件已明確標示：`節錄自：who · 版本 1。與全文屬同一原始文件，不能計為獨立證據。` 此項已不再容易被誤認成第二份獨立證據。
- 舊 run 沒有候選時，人工審閱頁顯示 `本次沒有可接受或修改的候選；可以拒絕並記錄原因。` 實際檢查選項狀態，`接受` 與 `修改` 均為 disabled，只有 `拒絕` 可選；沒有提交任何審閱。

### 仍有實質問題 1／中：歷史 run 的病例版本與模型來源不易辨認

**重現**

1. 在病例工作台選擇目前的 `agent-complete · revision 4`。
2. 開啟歷史 run `91ddb348`。
3. 查看分析結果頂端與「分析當時的病例情境」。

**實際所見**

- 全頁病例區顯示目前選取的是 `agent-complete · revision 4` 與 `28 個病例 · 版本 4`。
- 歷史分析標題只顯示 `獨立代理協作 · 選用已設定模型 · 91ddb348-f6a6-4576-9926-989df2447128`。
- 「分析當時的病例情境」有完整快照內容，但沒有 `病例版本` 或 `revision` 欄位。
- run 頂端沒有實際模型名稱；必須到證據與流程逐一展開 Agent，才看得到 `模型：gpt-4.1-mini`。

**醫師可能如何誤解**

讀者容易把目前選取的 revision 4 當成歷史 run 的輸入版本。若病例在 revision 3 與 revision 4 間有更動，只看這一頁無法確認該結果究竟基於哪一版。`選用已設定模型` 也不足以支援稽核或重現。

**建議**

- 在 run 標題直接顯示 `分析病例：agent-complete · revision N`，並與 `目前病例：revision 4` 分開。
- 顯示各 Agent 的實際模型；若相同可彙總，若不同則列簡短清單。
- 「分析當時的病例情境」標題旁加入不可變的病例 revision 或 snapshot 識別。

### 仍有實質問題 2／中：待確認清單保留重複的技術列，操作下一步不夠聚焦

**重現**

1. 開啟歷史 run `91ddb348` 的分析結果或人工審閱。
2. 查看 `需要補充或確認`。

**實際所見**

- 兩列完全相同的 `evidence_context`：`輸入長度限制省略 15 個片段；未讀取部分不能視為已核對`。
- 下一步均為：`檢視引用快照，必要時縮小文件範圍重新分析`。
- 另列：`clinical_agent：Agent 輸出格式、藥品或引用檢查未通過`。

**醫師可能如何受阻**

兩列看不出分別屬於哪個 Agent、哪批文件或哪些藥品，容易被當成重複錯誤。`clinical_agent` 仍是技術名稱，且在人工審閱頁沒有直接指出應開啟哪個 Agent 查看已有資料與失敗原因。

**建議**

- 合併相同列，顯示受影響的 Agent、文件範圍與藥品數。
- 將 `evidence_context`、`clinical_agent` 改為可讀標籤，原始代碼收進技術折疊。
- 在人工審閱頁提供 `查看臨床風險 Agent 失敗詳情` 與 `查看被省略的引用範圍` 的直接連結。

### 1.4.0 新分層的驗收界線

本次只確認舊歷史 run 在新版 UI 的相容呈現。畫面沒有可識別為 1.4.0 新合約輸出的 live run，因此沒有宣稱以下功能已經以實際新版資料驗收：

- 新分層逐藥表的完整資料流。
- 五項聲明複核的實際內容與狀態轉換。
- 第二層候選在真實新版資料下不能直接接受。

舊 run 的「無候選」審閱限制已確認：接受與修改被禁用。這不能替代有新版第二層候選時的瀏覽器驗收。

## 兩項修正的窄範圍複驗

使用同一歷史 run `91ddb348-f6a6-4576-9926-989df2447128`，只複驗前述兩項問題；沒有查看其他 run、執行 live 或提交審閱。

### 通過：歷史病例版本與保存模型已直接顯示

分析結果頁實際顯示：

`獨立代理協作 · 模型：gpt-4.1-mini · 91ddb348-f6a6-4576-9926-989df2447128`

`分析當時病例：agent-complete · 病例版本 3 · 模型：gpt-4.1-mini · 2026/10/06 20:08:05 · 流程 agent-led-1.3.1`

證據與流程頁及人工審閱頁也顯示相同的「分析當時病例」資訊。這已能清楚區分目前選取的 revision 4 與歷史分析使用的病例版本 3，也不再需要逐一展開 Agent 才能得知保存模型。

此項未再發現實質誤導或操作阻擋。

### 通過：待確認來源、中文標籤、合併與跳轉均符合預期

人工審閱頁的待確認表格實際顯示：

- `證據 Agent` → `文件片段未完整納入` → `輸入長度限制省略 15 個片段；未讀取部分不能視為已核對`
- `臨床風險 Agent` → `文件片段未完整納入` → 相同影響文字
- `臨床風險 Agent：Agent 輸出格式、藥品或引用檢查未通過`

兩筆 evidence context 雖然影響文字相同，但來源 Agent 不同，因此保留為兩列，沒有錯誤合併。技術欄位 `evidence_context` 已改為中文 `文件片段未完整納入`。

實際操作結果：

1. 證據 Agent 列的 `查看此步驟` 會切到「證據與流程」，並展開 `03 證據 Agent · 需確認`。
2. 臨床風險 Agent 列的 `查看此步驟` 會切到同頁，並展開 `04 臨床風險 Agent · 執行失敗`。
3. `查看錯誤步驟` 也會切到同頁並展開 `04 臨床風險 Agent · 執行失敗`。

三個跳轉均能立即看到對應內容，未發現跳錯角色、沒有展開或無法理解下一步的問題。

前述兩項問題可標記為已修正。1.4.0 新分層 live 驗收界線仍維持不變。
