# Agent-led 1.8.0 修正與驗證

驗證日期：2026-10-13。此版本修正分析排程與來源補正流程；驗證未呼叫付費模型。

## 修正項目

| 問題 | 處理方式 |
| --- | --- |
| 18 藥一起送出，但臨床模型反覆只回第一藥 | 臨床及整合通常每批三藥，限制每批回覆筆數；先完成首次分批，再逐藥補答。完整病例與 AST 索引保留。 |
| 漏答和引用補正共用角色重試次數 | 每藥分開計算漏答／格式補正及引用補正，仍遵守全程時間及呼叫預算。 |
| 已列引用卻未選原文，初評被降為未知 | 附上模型自己的先前回覆與缺漏引用，要求模型補選、刪除不支持的引用或修正結論。 |
| 引文內容未支持聲明，如提及原文沒有的交互作用藥名 | 提供具體來源驗證問題及該藥已檢索的其他原文，要求重新選取或修正；不能自動判定支持。 |
| `drug_rows` 全域警示阻擋已完成藥物 | 警示只歸屬實際未完成藥物；補答完成後清除。實際全域病例問題仍保留並顯示。 |
| 整合借用其他藥物／其他面向引用 | 逐項驗證引用是否來自本藥同面向專家評估，錯誤時要求補正並維持待確認。 |
| AST 混用目前判讀依據和比較欄位 | 明確要求選用目前依據的非空類別欄位；來源不符時補正，缺值仍未知，不推算 MIC。 |
| 證據已準備但批次未執行 | 逐藥記錄納入呼叫與尚未送出的片段數，與輸入長度省略分開呈現。 |

每次嘗試保存 `kind`、`requested_drugs`、`input_evidence_refs`、`validation_feedback` 與引用補正資訊。批次或補正失敗會保留先前已驗證的其他藥物。

## 保留的設定

- 逐藥檢索上限 30 種；每次查詢四個主要命中。
- 全程 1,200 秒（20 分鐘）、最多 24 次模型呼叫。
- 每藥、每種補正最多三次重試；總預算優先，不能保證每項補正都會取得三次機會。
- 18 藥無補正時共 16 次呼叫。明確降低呼叫上限或藥物更多時，批次會增大，以保留後續角色的首次評估。
- 既有輸入、輸出、檢索和來源驗證界線保留；未知或錯誤來源不會為了通過檢查而自動轉成支持。
